# 六本豆 Lite 0.3.3 · 离线授权版

分发使用桌面的 `六本豆Lite-安装包-0.3.3.exe`（约 26.5 MiB）。当前用户安装，带桌面、开始菜单快捷方式及卸载入口。首次启动复制授权申请码，管理员使用桌面 `lite六本豆授权工具.exe` 粘贴申请并签发激活码，用户粘贴激活后进入工作台。旧 `.lbdreq` / `.lic` 文件仍可使用。授权验证不访问服务器；云端连接仍在工作台用邀请码激活。

0.3.3 增加“复制申请码 → 签发并复制激活码 → 粘贴激活”，授权工具自动记住期限，支持记录搜索、重新复制和载入设备续期。原有工作区外路径、用户当前指令优先和 curl 接入方式继续使用。

双击 **LiubendouLite.exe** 打开独立 Windows 桌面窗口。关闭窗口会留在托盘，保持云端连接；右键托盘「退出并停止服务」或双击 **停止.cmd** 退出。分发包自带 Node.js，接收者无需安装开发工具。

## 直接体验

1. 每位用户在自己的电脑运行 EXE 安装包，打开 GUI，复制离线授权申请，收到管理员的激活码后粘贴激活。
2. 在「接入与提示词」粘贴一个邀请码，激活自己的电脑。
3. 点击「新建任务」，选择自己的项目文件夹。
4. 点 **复制给 Agent**，把整段提示词发给云端 Agent。模板采用用户指定的授权说明和六步 curl / Streamable HTTP 流程，自动填入当前电脑与任务的公网链接。
5. 工具在该用户的电脑执行。执行事实自动记录，关键决定通过 `memory_set` / `project_note` 保存；阶段结束由 Agent 用 `project_checkpoint` 更新任务概况。
6. 管理员 GUI 的「生成分享邀请码」可以给其他人生成一次性、24 小时有效的邀请码。普通客户端不含管理员权限，不显示此按钮。

连接提示词的模板可以在 GUI 编辑，必须保留 `{{MCP_URL}}`。预览会隐藏地址中的凭据，实际复制包含完整可用链接。正常重启、断线重连不改变链接。文件工具和任务流程兼容旧版基础接口。

## 数据与行为

- 发行版数据保存在 `%LOCALAPPDATA%\LiubendouLite\data`，其中 `memory.sqlite` 使用 WAL 保存任务、记忆、概况和活动。卸载保留本机数据；开发模式默认使用源码目录 `data`。
- 每个 MCP 地址绑定一个任务。相同项目目录下的不同任务也不共享记忆。后台命令的查询与取消同样受任务归属约束。
- 服务自动记录工具活动；关键记忆通过 `memory_set` / `project_note` 保存。`project_context` 返回概况、后续变化和当前修订号。
- `project_checkpoint` 需要 `expected_revision`，避免总结期间发生新活动却被旧概况覆盖。每份概况保存所依据的记忆 ID/版本和最近活动 ID。
- 语义概括由当前 Agent 或用户填写，服务不调用其他模型，不会读取其他应用聊天。新活动会标为待更新并附在交接中。
- 检索使用本地中英文词法评分。它不具备向量模型的同义理解能力，无词面关联时可能检索不到。
- 当前概况、最近关键记忆和活动按数量限制返回；`memory_get` 支持分页，`memory_search` 检索任务的全部当前记忆。完整数据可通过「导出此任务」保存。
- 归档任务不会删除数据；左侧「查看已归档任务」可以找到并恢复。
- 本地服务只监听 `127.0.0.1`，主动建立到中转网关的 WebSocket 连接。服务器按设备转发 MCP 请求，不保存本机文件、任务记忆或工具正文。
- 每台电脑独立注册，设备凭据不共享。公网任务链接使用任务 ID 派生的 HMAC 凭据，修改设备或任务 ID 后不能沿用原链接的凭据。设备身份保存在 `data/relay.json`，不可发给其他用户。
- `data/gateway-admin.json` 只在管理员电脑存在。分发包不包含 data、管理员凭据、设备身份、SSH 私钥或原用户的自定义提示词。
- `src/relay.ts` 负责心跳、自动重连和公网实际初始化验证，GUI 展示本机服务、中转连接和公网握手三项状态。离线时网关明确返回 503；撤销设备后链接失效。
- 工作区是相对路径和命令 cwd 的默认起点。文件、补丁、搜索和命令工具按用户指令支持工作区外路径（例如桌面），解析符号链接，受当前操作系统账户权限约束。工具按任务保存记忆和执行记录，文件位置不决定记忆归属。
- 复制交接提示词与 MCP 初始化说明都会附上操作范围：当前用户指令优先于默认流程和旧交接；已有明确授权不重复确认，目录实际位置由本机查询。
- 服务重启后，内存中的后台命令句柄不能继续使用，已保存的执行记录仍可读取。使用「停止.cmd」会先取消本服务启动的后台命令。

GUI 使用系统 WebView2，不捆绑 Electron。没有 Python、向量服务或额外模型调用。需要 Windows x64、.NET Framework 4.8 和 WebView2 Runtime。未做旧版业务数据自动迁移。

## 离线授权和代码保护

- 设备申请包含产品、机器标识和设备公钥，不包含私钥。许可证使用 Standard.Licensing ECDSA 签名，支持永久和精确到签发时刻的限期授权。
- 设备私钥由 Windows DPAPI CurrentUser 保护，授权绑定电脑与 Windows 账户。本机身份资料丢失后需要重新申请。
- 自己的 Node 后端及五个旧工具模块打包为 AES-256-GCM 加密内容；分发包不带自己的明文后端。授权有效时，原生 GUI 验签、核对设备与构建清单，解封装内容密钥，经私有标准输入管道交给内存加载器。密钥不放在命令行或环境变量中，也不写回明文代码文件。
- 原生授权入口使用 Obfuscar 2.2.50 混淆。构建清单及加载器摘要有签名，修改加载器或加密包会拒绝启动。服务逐请求检查到期，使用单调时间限制回拨；原生 GUI 定期复核本机许可证，退出或失去心跳会停止后端。
- 续期从 GUI 左下角或托盘“离线授权与续期”粘贴新激活码或导入新证书，再退出并重新打开。开发模式不受此发行版授权入口限制，不能向用户分发源码开发目录代替加密包。
- 签发工具和 `Documents/LiubendouLite-LicenseAuthority` 只由管理员保存，发行包不包含签发私钥、内容密钥、个人 data 或设备凭据。离线保护有逆向和本机管理员修改的实际边界，不承诺无法破解。

## 中转服务器

`gateway/` 是独立 Node.js 中转服务，唯一第三方依赖为 ws。服务器使用现有域名，通过 Caddy 转发至本机 8878；systemd 以专用低权限用户运行。SSH 私钥只用于管理员部署，不进入客户端运行链路。

当前限制为 128 个在线设备、32 个并发请求、每设备 4 个并发请求；这些是保护上限，不代表已经验证的容量。超限返回 429。已验证两个隔离客户端的并发、路由隔离、单次邀请码、掉线重连和撤销授权；尚未进行多台物理机和长期高并发测试。

管理员凭据只能调用邀请码、设备列表和撤销接口。服务器保存设备凭据与邀请码的散列，工具执行和记忆检索仍由各电脑完成。

## 开发与验证

```powershell
npm ci
npm run build
npm test
npm start
```

环境变量：`LBD_PORT`（默认 8777）、`LBD_DATA_DIR`（默认本目录 data）。stdio 入口：`node dist/index.js --stdio --task <任务ID>`，需要本机服务已启动。构建桌面窗口用 `tools/build-desktop.ps1`，生成纯净客户端目录用 `node tools/package-client.cjs`。

上述命令用于开发模式。离线授权发行版使用 `node tools/build-protected.cjs`，随后 `node tools/build-installer.cjs` 构建 EXE。两步分别输出 `release/LiubendouLite-0.3.3-win-x64-licensed` 和 `release/LiubendouLite-Setup-0.3.3.exe`，不要把开发模式产物作为授权版分发。Windows Node 24 及官方 .NET Framework 编译器、NSIS 3.11 用于本机构建。

历史 0.3.0 验证（非本次 0.3.3 结果）：原有 Node 回归 19 项、签发与本机授权类 37 项、加密成品客户端 24 项、安装卸载 18 项均通过；另从现有服务器用真实 curl 经公网完成加密客户端的文件、命令、记忆和概况调用。未做两个不同物理电脑、标准用户账户或长期并发压力测试。证据见 `../docs/runs/LITE-RELEASE-20261107/summary.md`。

源码是严格类型的 TypeScript，页面为原生 HTML/CSS/JavaScript。MCP 使用官方 SDK，复用了旧版五个独立工具模块；无需启动或依赖旧版应用。

此预览版仅承诺已实现接口的兼容；旧版 69 个外显工具并未全部移植。原有提示词使用的基础文件、命令、计划和交接流程已覆盖，结构化多人独立验收等高级协作流程未移植。

旧版 v2 的本地程序和数据未删除。服务器旧报道系统按用户要求移除，其备份记录在 `../docs/runs/SERVER-CLEANUP-20261107/summary.md`。网关部署前的 Caddy 配置备份保留在服务器，回滚时应停止网关后恢复该配置并校验。

0.3.3 按用户要求只编译与构建，未运行测试或安装验证。

## macOS 体验版

Mac 原生窗口与钥匙串授权源码在 `native/macos`，功能对齐 0.3.3。使用 `tools/prepare-macos.cjs` 在 Windows 本地加密核心并签署 Mac 构建清单，生成 `macos-build`；该目录是可推送的独立私有 Git 仓库，不含签发私钥、内容密钥或个人 data。云端工作流只编译和打包，不测试、不执行 Apple 公证，生成两个临时签名 DMG。

管理员使用桌面 `lite六本豆授权工具-Windows和Mac通用版.exe`，继续在原 Windows 本机签发。原 `lite六本豆授权工具.exe` 保留，未打断正在使用的窗口。Mac 设备使用签名 JSON 许可格式及钥匙串 RSA 私钥；Windows 既有 XML 许可继续支持。
