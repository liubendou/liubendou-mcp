# AI 协作作业协议（ai-protocol.md）

> 来源：借鉴《Claude 工程能力与长程任务分析》可复制清单，结合本机实际（ops-notes.md 的防呆规矩 + 看板租约机制）。
> 适用：今后任何 AI 在这台机器/这套产品上接活。与 `docs/ops-notes.md`（技术防呆）配套：那边管"怎么不踩坑"，这边管"怎么把活干完、干对"。

## 0. 一句话

**环境状态（看板/进度文件/CHANGELOG）替代模型记忆；完成以验收项为准，不以自称准。**

## 1. 接手流程（每次开场固定顺序）

1. `agent_register` 注册 → 拿 agent_id（换 AI 必注册新 id）。
2. `task_status` 看板 → `task_claim` 认领**一个**任务（租约中勿抢别人的）。
3. 读 `CHANGELOG.md` 尾部 + `docs/plan.md` 状态 + 任务相关进度文件——先懂现状再动手。
4. 动手前把任务拆成子步骤（≤5），写清每步的**可验证结果**。

## 2. 一次一事（治半途而废）

- 一个租约周期只做一个任务；子步骤串行，做完一步 `task_progress` 报一步。
- 禁止一口气改多处"顺手都修了"——每处改动可回滚、可单独验证。
- 中途被打断/换手：先落进度文件，再交接；禁止只留"在做了"。

## 3. 验收项（acceptance）——完成的唯一标准

- 任务描述里带验收项清单，JSON 形式（模型少乱改 JSON）：
  ```json
  {"acceptance": [
    {"id": "a1", "text": "verify.ps1 五项全过并存档", "pass": false, "evidence": ""},
    {"id": "a2", "text": "0.1.0 目录基线比对一致", "pass": false, "evidence": ""}
  ]}
  ```
- `pass:true` 必须附 `evidence`（文件路径/命令输出摘录/存档文件名）。
- **验收项不许改文案来凑通过**（对应"删/改测试不可接受"）；要改验收项=重新和用户确认。

## 4. 生成 / 评估分离

- 实现者不自签验收：同一任务里，动手的人只交证据；有条件时由另一个 agent/会话按**用户路径**复核（真开界面/真跑 verify，不是只看代码）。
- 本机已有惯例：打包的产物用 `verify.ps1` 独立验证并存档（见 `docs/verify-p9.md`），推广为：凡涉产物的任务都留独立验证存档。
- bug 报告具体到 `文件:行号` + 复现步骤 + 期望/实际。

## 5. 上下文与汇报纪律

- 长活的状态写在**文件里**（进度文件、CHANGELOG、交接），不靠会话记忆；每完成一段落就落盘。
- 工具输出只取必要片段；token/会话号/密钥**零出现**。
- 汇报格式：干了什么（文件/证据）→ 未验证项显式列出 → 下一步。不虚报、不夸大、不隐藏失败。
- 失败三次换方法，并把根因记入 CHANGELOG「踩坑记录」/ ops-notes。

## 6. 红线（与 ops-notes.md 一致，违反=任务失败）

- 只读区（交接包/0.1.0 便携版/六本豆/六本豆-lab）零改动；服务器与私钥零触碰。
- 验证/打包前 `Stop-Process -Name '六本豆mcp' -Force`（窗口 × 只是缩托盘）。
- 每处变更进 CHANGELOG（改了什么/为什么/怎么回滚/验证）。

## 7. 规矩也要消融

每条规矩都编码了"当前模型做不到什么"的假设，假设会过期。定期（大版本/季度）复盘：哪条已无效就删，别让规矩堆成死重。

## 8. 现场文件与证据（P4）

**三条铁律**：临时文件进 `ops-tmp`、证据进 `docs/runs`、收工清场。

- **临时现场**：一律 `C:\Users\Administrator\ops-tmp\`（纯 ASCII 文件名）：`<taskid>-progress.txt`（时间戳|做了什么|证据在哪）、`<taskid>-done.txt`。禁止散落在桌面/用户根目录。
- **永久证据**：`v2\docs\runs\<taskid>-<日期>\`——verify 输出、基线比对、评测结果、`summary.md`。任务 id 与看板（T14 等）对齐。产品级最新验证指针：`docs/verify-latest.md`。
- **命名铁律**：临时文件纯 ASCII（GBK 坑）；证据目录 = 任务 id；CHANGELOG 只记结论与回滚，证据放 runs。
- **检查点节奏**：每完成一个子步骤 → `task_progress` + 进度文件追加一行；任务收尾 → 证据归档 runs/ → CHANGELOG 条目 → 清场 ops-tmp → `task_complete`。
- **辅助脚本**：`tools\runlog.ps1`（dot-source 后 `Start-RunLog -Task T15` / `Add-RunLog "文本"` / `Complete-RunLog -Summary "..." -Attach "文件"`，自动归档+清场）。
